# Aver 0.12.0 "Ledger" — Design

## Context

0.11.0 "Oracle" added proof export for effectful functions via per-method oracle stubs bound in `given` clauses. Classified effects (`Random`, `Http`, `Disk` read-side, `Tcp.send`/`.ping`, `Time.*`, `Console.readLine`, non-modal `Terminal.*`, `Args.get`, `Env.get`) can be quantified over as symbolic oracles in Lean 4 and Dafny laws.

0.12.0 "Ledger" extends this to **namespace-level stateful effects** — `Env` writes, `Disk` full read/write, modal `Terminal`, and `Tcp` sessions with per-connection state. The mechanism is threading a user-chosen state value through the sequence of calls in a verify block; the proof backend quantifies over the state + the model. Protocol compliance (e.g. "no `Tcp.readLine` after `Tcp.close`") becomes provable without adding linear types, session types, or any new type-system feature.

## Core mechanism: state threading + capability intrinsics

Where Oracle v1 has per-method stubs (`stub : (BranchPath, Int, args...) -> T`), 0.12 adds namespace-level **capability models**: a bundle per namespace of per-method stubs sharing one state type `S`. Each method threads state in and out:

```
method_stub : (BranchPath, Int, S, args...) -> (S, returnType)
```

The compiler rewrites each call to a classified effect inside a verify-lifted function so that the previous stub's returned state becomes the next stub's input. State threads through `match` arms, `?` error propagation, and helper calls; every effectful fragment in the lowered form has the shape `(state_in) -> (state_out, value)`.

Backend codegen emits functions generic over `S`:

- Lean 4: `def foo {S : Type} (model : NsModel S) (state : S) : S × ret := ...`
- Dafny: `function foo<S>(model: NsModel<S>, state: S, ...): (S, Result)`

`NsModel S` is represented internally as a `structure`/`datatype` — not exposed as surface Aver syntax.

**Lifted defs are generic over `S`; law theorems are not.** Each verify law instantiates the lifted def with the concrete initial state from its `given` clause. A stdlib-default `given tcp: Tcp = [TcpModel]` supplies the default init; a `[model(myInit, ...)]` supplies `myInit`. Theorems look like:

```
theorem fn_law : (let (finalState, result) := fn init model args; result = expected ∧ predicate finalState)
```

They do NOT quantify `∀ initState`. A universally-quantified "for all initial states" theorem needs a user-supplied `invariant(initState)` precondition and a separate extension; **out of scope for 0.12**. Strict stdlib models ship only with the default init — arbitrary initial `TcpState` with pre-existing violations, broken `nextId`, or pre-closed connections are never exposed to the proof backend.

## Three intrinsic forms in `given` RHS

The parser sees regular expressions (`FnCall("model", ...)`, `RecordCreate("TcpModel", ...)`, `Ident("TcpModel")`). The checker interprets these contextually when the LHS is a namespace path (not a method path). Two new verify/proof-only intrinsics plus per-namespace stdlib constructors:

### 1. Bare stdlib default

```aver
given env: Env = [EnvModel]
given tcp: Tcp = [TcpModel]
```

Uses the stdlib default model + default initial state for the namespace. Metadata table (see "Single source of truth") resolves the constructor, default state, and strict compliance predicate. **Strict by default.**

### 2. Custom model, protocol-sensitive only

```aver
given env: Env = [model(myInit, EnvModel(get = myGet, set = mySet))]
```

User-supplied initial state + per-method stub overrides. Compiler infers `S` from `typeOf(myInit)`, validates each method stub against the namespace's method signature. **No auto-obligation on final state.** Proof catches protocol violations only when they affect the observable result.

### 3. Custom model with explicit compliance

```aver
given env: Env = [strict(
    model(myInit, EnvModel(get = myGet, set = mySet)),
    MyState.noViolations
)]
```

Wraps a custom model and attaches a user-supplied compliance predicate. Generated theorem gets an extra conjunct `predicate(finalState)`. Predicate must be a pure top-level function with signature `Fn(S) -> Bool`, exportable to Lean 4 and Dafny (no effects, no opaque helpers). Lean theorem renders it as `predicate finalState = true` (or `predicate finalState` when generating `Prop` in proof-mode emit, depending on backend context).

**Strictness is always explicit.** Never inferred from field names or any structural heuristic. If you want compliance and aren't using a stdlib default, wrap in `strict(...)`.

### List semantics (cartesian, preserved from Oracle v1)

```aver
given env: Env = [EnvModel, model(myInit, EnvModel(...)), strict(...)]
```

Each element is an independent model expression. Law must hold across all elements. If elements have different state types, generate separate per-element theorems (not a unified theorem over heterogeneous `S`).

## Example: Tcp session with protocol compliance

The stdlib `TcpState` carries a connection map, a sticky violations list, and an in-state counter for deterministic connection handles:

`Tcp.Connection` is an existing Aver record with fields `id: String`, `host: String`, `port: Int`. Since Aver `Map<K, V>` restricts `K` to `Int | Float | String | Bool` (record keys are rejected), the state indexes connections by their string `id`, not by the record itself.

```aver
type ConnPhase
    Active
    Closed

type ProtocolViolation
    ReadOnClosed(String)
    WriteOnClosed(String)
    CloseOnClosed(String)
    UnknownConn(String)

record TcpState
    connections: Map<String, ConnPhase>    // keyed by conn.id
    violations:  List<ProtocolViolation>
    nextId:      Int
```

Stub methods (example — stdlib ships this as the default `TcpModel`):

```aver
fn stubConnect(path: BranchPath, n: Int, state: TcpState, host: String, port: Int) -> (TcpState, Result<Tcp.Connection, String>)
    connId = "tcp-" + String.fromInt(state.nextId)
    conn   = Tcp.Connection(id = connId, host = host, port = port)
    newState = TcpState.update(state,
        connections = Map.set(state.connections, connId, ConnPhase.Active),
        nextId      = state.nextId + 1,
    )
    (newState, Result.Ok(conn))

fn stubReadLine(path: BranchPath, n: Int, state: TcpState, conn: Tcp.Connection) -> (TcpState, Result<String, String>)
    match Map.get(state.connections, conn.id)
        Option.Some(ConnPhase.Active) -> (state, Result.Ok("response"))
        Option.Some(ConnPhase.Closed) ->
            v = ProtocolViolation.ReadOnClosed(conn.id)
            (TcpState.update(state, violations = List.prepend(v, state.violations)), Result.Err("closed"))
        Option.None ->
            v = ProtocolViolation.UnknownConn(conn.id)
            (TcpState.update(state, violations = List.prepend(v, state.violations)), Result.Err("unknown"))

fn noViolations(state: TcpState) -> Bool
    List.len(state.violations) == 0
```

Connection handles come from `state.nextId` via a string `id` format; zero reliance on an opaque `fresh(path, n)` axiom. Equality checks on `Tcp.Connection` in law bodies can compare `conn.id` directly — no extra injectivity axiom needed in Lean/Dafny.

Verify under the stdlib default catches both "affects result" and "ignored violation" cases:

```aver
fn bad(host: String) -> Result<String, String>
    conn = Tcp.connect(host, 1)?
    Tcp.close(conn)
    ignored = Tcp.readLine(conn)    // protocol violation, result unused
    Result.Ok("response")

verify bad law alwaysOk
    given tcp: Tcp = [TcpModel]
    bad("host") => Result.Ok("response")
```

Generated Lean theorem:

```lean
theorem bad_law_alwaysOk :
    let (finalState, result) := bad BranchPath.Root TcpModel "host"
    result = Result.Ok "response" ∧ TcpState.noViolations finalState = true
```

`bad` fails the compliance conjunct because `stubReadLine` appended `ReadOnClosed(conn)` to violations, so `TcpState.noViolations finalState = false`. Proof rejected.

Under plain `model(...)` (no `strict`), only the first conjunct would be generated — `bad` would prove, because the ignored `Err` doesn't affect the observable result. That's **protocol-sensitive verification**, the weaker guarantee.

## Verification semantics summary

| form | compliance guarantee |
|---|---|
| `[NsModel]` (stdlib default) | full: result = expected AND `predicate(finalState)` |
| `[model(init, NsModel(...))]` | protocol-sensitive only (catches violations that affect result) |
| `[strict(modelExpr, predicate)]` | full: result = expected AND `predicate(finalState)` |

Full compliance is not a property of the state-threading mechanism alone — it requires an explicit predicate attached via the stdlib metadata path or the `strict(...)` wrapper. Sticky violations + `strict(...)` + predicate are the added machinery over bare state threading.

## Scope

### In scope

- Three intrinsics (`NsModel`, `model(init, NsModel(...))`, `strict(modelExpr, predicate)`) in namespace-path `given` RHS
- Parser generic; checker does contextual interpretation
- State-passing lowering transform through `match`, `?`, and helper calls (stateful effects reaching `!` / `?!` branches are rejected — see Out of scope)
- Generic-over-`S` codegen in Lean 4 and Dafny
- Stdlib default models: `EnvModel`, `TerminalModel`, `TcpModel`, `DiskModel`
- Rust metadata table as authoritative schema for per-namespace model shape
- Golden tests: each canonical example law runs through `aver verify` + `lake build` + `dafny verify` in CI; drift fails the build
- Mixing-rules checker validation with structured diagnostic slugs

### Out of scope for 0.12

- **User-defined effects.** The "effect module with state clause" shape collides with Aver core rules (explicit signatures, no partials/closures). Open design problem, not blocked on 0.12.
- **Stateful models inside `!` / `?!` (independent parallel products).** Rejected with diagnostic. Left-to-right merge of concurrent state writes isn't schedule-invariant; explicit commutative-monoid merge semantics is a separate design.
- **Recursive effectful state laws.** Lean termination proof + state threading across recursive calls is additional work; rejected in 0.12 with diagnostic.
- **Alias use of `given tcp: Tcp = ...` binding name as a value in law body.** The namespace model is an invisible binding used by the rewrite of `Tcp.readLine` etc. — not a normal Aver value. Cartesian list with heterogeneous `S` emits per-element theorems (each under its own model), and alias reference in body is simply not a feature in 0.12. Wanting `env.someField` in a law body is a later-minor discussion.
- **`RandomModel` / `HttpModel`.** `Random` and `Http` remain under Oracle v1 per-method oracles. Stateful random streams or HTTP session state are a separate scope expansion.
- **`HttpServer.*`.** Event loop / lifecycle is not a unit of proof. Handler callbacks are already provable under Oracle v1 as regular functions.

## Stdlib default models

### `EnvModel`

- State: `record EnvState { vars: Map<String, String> }`
- Default init: `EnvState(vars = Map.empty)`
- Methods: `get(key) -> Option<String>`, `set(key, value) -> Unit`
- Strict predicate: `fn alwaysOk(s: EnvState) -> Bool { true }` — Env has no protocol violations to track in the reference model; strict adds no obligation beyond result equality, but the form is preserved for consistency across namespaces

### `TerminalModel`

- State: `record TerminalState { rawMode: Bool, color: Option<String>, buffer: List<TerminalOp>, violations: List<TerminalViolation> }`
- Default init: `TerminalState(rawMode = false, color = Option.None, buffer = [], violations = [])`
- Methods: `enableRawMode`, `disableRawMode`, `setColor(String)`, `resetColor`, `print`, `size`, `readKey`, others as classified (`color` is a `String` because that's what the existing `Terminal.setColor` takes; no new `Color` type is introduced in 0.12)
- Strict predicate: `noViolations`
- Violations: conservative set only — `DisableRawModeWithoutEnable` (sensible because runtime also fails on disable-without-enable). `ResetColorWithoutSet` is NOT a violation — terminals treat reset as idempotent and real code often calls it unconditionally on cleanup; default strict model must not reject code the real runtime accepts.

### `TcpModel`

- State shape shown in the example above (connection map, violations, nextId)
- Methods: `connect`, `writeLine`, `readLine`, `close`
- Strict predicate: `noViolations`
- **Deterministic protocol model, not real-network semantics.** Documented explicitly: laws prove against this model; transfer to real-runtime behavior is only as good as the model's fidelity to the protocol you actually need.

### `DiskModel`

- State: `record DiskState { files: Map<String, String>, violations: List<DiskViolation> }`
- Default init: `DiskState(files = Map.empty, violations = [])`
- Methods covered: `readText`, `writeText`, `appendText`, `exists`, `listDir`, `delete`
- Methods NOT covered in 0.12: `deleteDir`, `makeDir` — these are rejected by `DiskModel`. Using them inside a verify-lifted function under `given disk: Disk = [DiskModel]` (or any variant) produces a diagnostic `model-missing-method`: the model doesn't implement this method and the namespace-level capability can't silently fall through to an Oracle v1 per-method stub. User must refactor to avoid them inside verify-scoped paths, or wait for later minor.
- **Minimal MVP semantics, documented explicitly:**
  - files as a flat `Map<String, String>` keyed by normalized path string
  - no directory / file type distinction (dirs omitted in MVP; `listDir` operates on prefix match over flat map)
  - `listDir` returns lexicographically sorted list of paths matching a prefix
  - no permissions, no timestamps, no symlinks
  - `writeText` creates or overwrites; `appendText` creates-or-appends (matching real runtime — we do NOT flag missing-file-before-append as a violation, because real `Disk.appendText` also creates the file)
- Violations (tracked semantics, not strictness-by-default silliness):
  - `DeleteOfMissingFile` — runtime `Disk.delete` on a non-existent path returns an error; the model mirrors that
  - `ReadOfMissingFile` — same, runtime returns `Err`
- Strict predicate: `noViolations`
- **Deterministic in-memory reference, not real-filesystem semantics.** Documented explicitly.

## Mixing rules

Checker rejects combinations that would produce ill-defined semantics:

1. Per-method Oracle v1 `given` and namespace-level capability `given` for the **same namespace** in the same verify block:

   ```aver
   given read: Tcp.readLine = [stubFn]      // Oracle v1 per-method
   given tcp:  Tcp          = [TcpModel]    // 0.12 capability
   ```

   Rejected with error `capability-mixing`: `"cannot mix per-method Oracle v1 stubs with namespace-level capability model for the same namespace Tcp"`.

2. Default + custom elements in a single list form is permitted (both are model-domain elements):

   ```aver
   given env: Env = [EnvModel, model(myInit, EnvModel(...))]   // OK, cartesian
   ```

3. Heterogeneous `S` in a list: OK per-element, but using the alias in law body requires compatible state types across elements. Otherwise diagnostic `heterogeneous-model-list-alias-use` with suggestion to split.

## Lowering (state-passing transform)

Largest single piece of implementation work. Generalization of current `effect_lifting.rs` counter threading to full state threading. Specific invariants the transform must maintain:

- Every effectful expression fragment has shape `(state_in) -> (state_out, value)`
- `?` on `Err` returns the **post-call state**, not the pre-call state. The error short-circuit carries threaded state forward.
- `match`: subject evaluated once, producing `(post_subject_state, subject_value)`. Every arm starts from `post_subject_state`. Arms not taken do not "pass" state through — only the taken arm's result state surfaces.
- Helper function calls: lifted helpers take and return the namespace state types they touch. Helper signatures become `(ns_states_in, args) -> (ns_states_out, ret)`.
- Multiple namespaces threaded simultaneously: represented as a named record of per-namespace states, not positional. Positional tuples are too fragile against adding/removing namespaces.
- Recursion: rejected (Out of scope section).

## Single source of truth

Rust metadata table is the authoritative schema:

```rust
struct NamespaceModelSpec {
    ns_name: &'static str,                              // "Tcp"
    methods: &'static [(&'static str, Signature)],      // [("connect", ...), ...]
    default_state_ctor: RustFn,                         // how to construct default init
    strict_predicate: Option<&'static str>,             // "TcpState.noViolations"
    lean_struct_name: &'static str,                     // "TcpModel"
    dafny_datatype_name: &'static str,                  // "TcpModel"
}
```

The metadata table is authoritative for: field set, method signatures, default strictness, predicate name, per-backend codegen names. Model body implementations may be backend-specific (VM Rust, Lean emit, Dafny emit), but the schema is shared. **Golden tests** in CI run each canonical example law through `aver verify`, `lake build` (Lean), and `dafny verify` (Dafny); any divergence fails the build.

Target for a later minor: move default model bodies into a restricted Aver subset that emits to all three backends from one source. Out of scope for 0.12 — would block shipping.

## Diagnostic slugs introduced

- `capability-mixing` — per-method + namespace-level `given` for same namespace
- `stateful-in-independent-product` — stateful model inside `!` / `?!` (any branch/helper reaching a stateful NS)
- `recursive-stateful-law` — recursive effectful state law
- `strict-predicate-not-pure` — `strict(...)` predicate has effects or isn't a top-level pure function
- `model-field-unknown` — e.g. `TcpModel(foo = ...)` where `foo` isn't in the namespace method set
- `model-field-missing` — custom `model(init, NsModel(...))` must supply every namespace method; partial overrides rejected in 0.12
- `model-missing-method` — code uses `Disk.makeDir` or `Disk.deleteDir` under `[DiskModel]`; model doesn't cover these methods and can't fall through to Oracle v1

**Implementation note on emission.** The current checker has `TypeError { message, line, col }` and derives slugs via a post-classifier on error text. Wiring each slug above as a first-class structured diagnostic requires extending `TypeError` with an optional `slug: Option<&'static str>` field (or a parallel structured-error path). 0.12 can ship with classifier-based mapping for interim; the structured field is a cleanup task for the diagnostic framework, not blocker on the feature itself.
