### AppendOnlyTaskEventsWithFlatProjectState (2026-03-08)
**Chosen:** "TaskEventsPlusProjectState" — **Rejected:** "EverythingAsMutableState", "EverythingEventSourced", "InMemoryOnly"
> Task lifecycle is where reviewable history matters, so an append-only event log pays for itself. Projects are much shallower, and storing them as current state…

### AuditsStayAdjacentToEventsNotInsideThem (2026-03-08)
**Chosen:** "SeparateAuditLog" — **Rejected:** "EncodeAllAuditNarrativeAsTaskEvents", "NoAuditTrail"
> Reopen reasons and command traces are valuable to reviewers, but they should not change replay semantics for task state.
impacts: `recordEntries`, `loadEntries`

### NotificationsDeduplicateByKey (2026-03-08)
**Chosen:** "PersistAndSkipKnownKeys" — **Rejected:** "AlwaysEmitAgain", "NoNotificationHistory"
> Deadline and overdue rules can be re-run manually, so delivery needs a stable idempotency key or the CLI will drown in repeated warnings.
impacts: `emitNotifications`, `loadNotifications`
