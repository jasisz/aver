Aver runtime

Standalone WebAssembly modules for the Aver language runtime. Pair them with a thin user.wasm built via aver compile --target edge-wasm --optimize size — the runtime is cached once and shared across every program.

The model in one sentence. Aver emits small, explicit WASM modules. The runtime is shared. Effects are host-provided. WASI is just one bridge. Packaging (bundled vs edge) and effect host (JS / WASI / something else) are independent choices — every combination ships.

Quick start

A thin user.wasm imports two modules: aver_runtime (from this CDN) and aver (host effects you provide — see the next two sections for browser and standalone shapes). 

$ aver compile mygame.av --target edge-wasm --optimize size -o dist/

// Three-step instantiate: runtime → host effects → user program
const runtime = await WebAssembly.instantiateStreaming(
    fetch("https://averlang.dev/runtime/latest/aver_runtime.wasm"),
    {}
);
const user = await WebAssembly.instantiateStreaming(
    fetch("/dist/mygame.wasm"),
    {
        aver_runtime: runtime.instance.exports,
        aver: makeHostImports(runtime.instance.exports.memory),
    }
);
user.instance.exports._start();

Wiring up effects

Every user.wasm imports aver/* effects (Console.print, Time.unixMs, …) — the host environment provides them. Three usual paths:

JS host (browser, Node, Workers, Fastly Compute…)

Provide the aver/* imports as plain JS functions. Strings and other heap values arrive as (ptr, len) pairs into the runtime's linear memory — read them through a typed-array view of runtime.exports.memory. 

// Smallest viable shim — covers Console.* + Time + Random.
// Add more entries as your program declares more effects.
function makeHostImports(memory) {
    const decoder = new TextDecoder("utf-8");
    const readString = (ptr, len) =>
        decoder.decode(new Uint8Array(memory.buffer, ptr, len));

    return {
        console_print: (ptr, len) => console.log(readString(ptr, len)),
        console_error: (ptr, len) => console.error(readString(ptr, len)),
        console_warn:  (ptr, len) => console.warn(readString(ptr, len)),
        time_unixMs:   () => BigInt(Date.now()),
        random_int:    (lo, hi) => {
            const span = hi - lo + 1n;
            return lo + BigInt(Math.floor(Math.random() * Number(span)));
        },
    };
}

WASI host (wasmtime, wasmer, …)

On runtimes without JS, use the prebuilt aver_to_wasi.wasm shim — it satisfies aver/* imports against wasi_snapshot_preview1.fd_write. The CLI's --bridge wasip1 bundles it for you in one step: 

$ aver compile mygame.av --target wasm --bridge wasip1 --optimize size -o dist/
$ wasmtime dist/mygame.wasm
# No other host wiring needed.

Coverage today: Console.* and Format.value / Print.value. Other aver/* effects (Disk.*, Tcp.*, etc.) trap as unreachable in the bridge — wire them through the host directly until coverage lands.

Mixing edge packaging with any host

The artifacts on this page are the building blocks the CLI bundles internally. Publish them once at the URLs below and every --target edge-wasm binary you ship can share that runtime — paired with whichever effect host fits the deployment (browser shim above, the WASI bridge, Cloudflare Workers' JS bindings, anything else).

What's in each release

  • aver_runtime.wasm — alloc, GC, hashmap (HAMT), string / list / vector ops. Imported as aver_runtime by every edge-wasm binary.
  • aver_to_wasi.wasm — translation shim that satisfies a program's aver/* host imports against wasi_snapshot_preview1.fd_write. Optional — needed only when running through a WASI host such as wasmtime or wasmer. Browser and edge JS hosts (Cloudflare Workers, Fastly Compute, Node, Deno) provide aver/* directly; they don't need this shim.
  • .wat — human-readable disassembly of each .wasm. Inspect what's actually in the binary.
  • CHECKSUMS.txt — sha256 sums for every file in the directory.
